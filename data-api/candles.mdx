`getCandles` and `watchCandles` are the primary way to retrieve OHLCV (open, high, low, close, volume) candlestick data from TradingView. `getCandles` is a one-shot function that opens a connection, loads the requested bars oldest-first, then releases all resources before returning. `watchCandles` resolves once the initial history is loaded and then streams a fresh frozen snapshot on every subsequent bar update. Both functions support deep history spanning thousands of bars, date ranges, and alternative chart types like Heikin Ashi or Renko.

## getCandles

```typescript
import { getCandles } from '@mathieuc/tradingview/data';

// 100 most recent daily bars (shorthand)
const candles = await getCandles('BINANCE:BTCUSDT');

// 500 most recent 60-minute bars
const candles = await getCandles({ symbol: 'BINANCE:BTCUSDT', timeframe: '60', count: 500 });

const last = candles.at(-1);
// { time: 1700000000, open: 34100, high: 34500, low: 33900, close: 34300, volume: 1234.5 }
```

`time` is the bar open time as a Unix timestamp in **seconds**. The array is always sorted oldest-first.

### Options

<ParamField body="symbol" type="string" required>
  Exchange-qualified symbol such as `BINANCE:BTCUSDT`, `NASDAQ:AAPL`, or `FX:EURUSD`. A bare ticker without an exchange prefix lets TradingView pick the exchange. Use `searchMarkets` to discover valid symbols.
</ParamField>

<ParamField body="timeframe" type="string" default="'D'">
  Bar resolution. Minute values: `'1'`, `'3'`, `'5'`, `'15'`, `'30'`, `'45'`, `'60'`, `'120'`, `'180'`, `'240'`. Daily and longer: `'D'`, `'1D'`, `'W'`, `'1W'`, `'M'`, `'1M'`, `'3M'`, `'6M'`, `'12M'`. Seconds (account required): `'1S'`, `'5S'`, `'10S'`, `'15S'`, `'30S'`.
</ParamField>

<ParamField body="count" type="number" default="100">
  Number of most recent bars to return. When `count` exceeds a single server batch, deep history is loaded automatically in multiple requests. Ignored when `from` is set.
</ParamField>

<ParamField body="from" type="Date | number">
  `Date` object or Unix seconds. When set, loads every bar from this time up to `to`. Deep history is loaded automatically as needed. Providing `from` causes `count` to be ignored. Use `maxCount` as a safety cap.
</ParamField>

<ParamField body="to" type="Date | number" default="now">
  `Date` object or Unix seconds representing the newest bar time. Defaults to now. Bars exactly at this time may or may not be included depending on alignment.
</ParamField>

<ParamField body="maxCount" type="number" default="20000">
  Safety cap on the total number of bars loaded when using `from`. Prevents runaway deep-history requests for very old symbols.
</ParamField>

<ParamField body="chartType" type="string">
  Compute a derived chart type instead of standard OHLCV bars. Accepted values: `'HeikinAshi'`, `'Renko'`, `'LineBreak'`, `'Kagi'`, `'PointAndFigure'`, `'Range'`. Some types require a paid TradingView account.
</ParamField>

<ParamField body="chartInputs" type="object">
  Configuration inputs for the selected `chartType`. For example, Renko: `{ source: 'close', boxSize: 3, style: 'ATR', atrLength: 14, wicks: true }`. Range: `{ range: 1, phantomBars: false }`. Kagi: `{ source: 'close', style: 'ATR', atrLength: 14, reversalAmount: 1 }`.
</ParamField>

<ParamField body="currency" type="string">
  Convert prices to this currency code, e.g. `'EUR'` or `'USD'`. Uses TradingView's server-side currency conversion.
</ParamField>

<ParamField body="session" type="string">
  Trading session filter. `'regular'` returns only regular-hours bars. `'extended'` includes pre/post-market bars when available.
</ParamField>

<ParamField body="adjustment" type="string" default="'splits'">
  Price adjustment for equities. `'splits'` adjusts for stock splits. `'dividends'` adjusts for dividends. `'none'` returns raw unadjusted prices.
</ParamField>

<ParamField body="backAdjustment" type="boolean">
  When `true`, applies back-adjustment for continuous futures contracts.
</ParamField>

<ParamField body="timezone" type="string">
  Chart timezone for daily and longer bar alignment, e.g. `'America/New_York'` or `'Etc/UTC'`. Use `'exchange'` for the exchange's local timezone. Accepts any IANA timezone name that TradingView supports.
</ParamField>

<ParamField body="credentials" type="object">
  `{ session, signature }` — TradingView account cookies. See [Data API Overview](/data-api/overview#connection-options).
</ParamField>

<ParamField body="client" type="TradingViewClient">
  Reuse an existing open client. See [Data API Overview](/data-api/overview#connection-options).
</ParamField>

<ParamField body="clientOptions" type="object">
  Options for the connection opened by this call. See [Data API Overview](/data-api/overview#connection-options).
</ParamField>

<ParamField body="timeoutMs" type="number" default="15000">
  Timeout for the entire call in milliseconds. See [Data API Overview](/data-api/overview#connection-options).
</ParamField>

<ParamField body="signal" type="AbortSignal">
  Cancellation signal. See [Data API Overview](/data-api/overview#connection-options).
</ParamField>

### Return type

Returns `Promise<Candle[]>` where each `Candle` is:

<ResponseField name="time" type="number">
  Bar open time as a Unix timestamp in **seconds** (not milliseconds).
</ResponseField>

<ResponseField name="open" type="number">
  Opening price of the bar.
</ResponseField>

<ResponseField name="high" type="number">
  Highest price of the bar.
</ResponseField>

<ResponseField name="low" type="number">
  Lowest price of the bar.
</ResponseField>

<ResponseField name="close" type="number">
  Closing price of the bar.
</ResponseField>

<ResponseField name="volume" type="number">
  Volume traded during the bar.
</ResponseField>

<Tip>
  Raise `timeoutMs` when loading deep history with `from`. Loading thousands of bars requires multiple server round-trips that can exceed the default 15-second timeout. Values like `60000` or higher are common for large ranges.
</Tip>

### Anonymous access limits

Without credentials, TradingView limits historical data access. In testing, anonymous sessions can load approximately **7,000 one-minute bars**, and reference times (`to`) far in the past may be capped by the server. An empty result (no bars in the requested range) rejects with `NO_DATA`. When the server reported a data limit, the error message includes that detail.

### Code examples

<CodeGroup>

```typescript Basic count
import { getCandles } from '@mathieuc/tradingview/data';

// 100 most recent daily bars
const candles = await getCandles({ symbol: 'BINANCE:BTCUSDT', timeframe: 'D', count: 100 });

const last = candles.at(-1)!;
console.log(
  `${candles.length} bars for BINANCE:BTCUSDT;`,
  `last close ${last.close} at`,
  new Date(last.time * 1000).toISOString(),
);
```

```typescript Date range with from
import { getCandles } from '@mathieuc/tradingview/data';

// Every 4-hour bar over the last 7 days
const sevenDaysAgo = new Date(Date.now() - 7 * 86_400_000);
const candles = await getCandles({
  symbol: 'NASDAQ:AAPL',
  timeframe: '240',
  from: sevenDaysAgo,
  timeoutMs: 60_000, // deep history may need more time
});

console.log(`${candles.length} 4h candles since ${new Date(candles[0].time * 1000).toISOString()}`);
```

```typescript Heikin Ashi chart type
import { getCandles } from '@mathieuc/tradingview/data';

const haCandles = await getCandles({
  symbol: 'BINANCE:BTCEUR',
  timeframe: 'D',
  count: 50,
  chartType: 'HeikinAshi',
});

console.log('Heikin Ashi bars:', haCandles.length);
console.log('Last bar:', haCandles.at(-1));
```

```typescript Renko with custom inputs
import { getCandles } from '@mathieuc/tradingview/data';

const renkoCandles = await getCandles({
  symbol: 'BINANCE:BTCEUR',
  timeframe: 'D',
  count: 50,
  chartType: 'Renko',
  chartInputs: {
    source: 'close',
    sources: 'Close',
    boxSize: 3,
    style: 'ATR',
    atrLength: 14,
    wicks: true,
  },
});

console.log('Renko bars:', renkoCandles.length);
```

## watchCandles

`watchCandles` resolves once the initial history is loaded (and already delivered to `onData`), then keeps streaming a fresh immutable snapshot on every bar update. Call `stop()` when you no longer need updates.

```typescript
import { watchCandles } from '@mathieuc/tradingview/data';

const watcher = await watchCandles(
  { symbol: 'BINANCE:BTCUSDT', timeframe: '1', count: 10 },
  {
    onData(candles) {
      const last = candles.at(-1)!;
      console.log(new Date(last.time * 1000).toISOString(), 'close', last.close);
    },
    onError(error) {
      console.error('Watcher error:', error.code, error.message);
    },
  },
);

console.log(`Watching ${watcher.symbolInfo?.description}...`);

// Stop after 30 seconds
setTimeout(() => watcher.stop(), 30_000);
await watcher.closed;
console.log('Stopped.');
```

### Watcher properties

<ResponseField name="watcher.latest" type="readonly Candle[]">
  The most recent snapshot, oldest-first. Holds at most `count` bars. Available immediately after the promise resolves.
</ResponseField>

<ResponseField name="watcher.symbolInfo" type="SymbolInfo | undefined">
  Symbol metadata received from TradingView (exchange, currency, timezone, price scale, session, etc.). Set once the symbol resolves.
</ResponseField>

<ResponseField name="watcher.stop()" type="() => Promise<void>">
  Stops the watcher and releases its sessions and connection. Idempotent — safe to call multiple times.
</ResponseField>

<ResponseField name="watcher.closed" type="Promise<void>">
  Resolves when the watcher has fully stopped — after `stop()`, an aborted `signal`, or a fatal error.
</ResponseField>

<ResponseField name="watcher.isActive" type="boolean">
  `true` until the watcher stops.
</ResponseField>

### Notes

- `watchCandles` accepts the same chart options as `getCandles`, **except** `from`, `to`, and `maxCount`. Those are one-shot range options; the watcher always tracks the most recent `count` bars.
- Each `onData` call receives a **frozen** array of frozen `Candle` objects — do not mutate them.
- Errors that occur before start-up reject the promise. After start-up, errors are delivered to `onError`; fatal errors (disconnection, symbol or series errors) also stop the watcher.
- There is **no automatic reconnection**. Start a new watcher when `closed` resolves if you need to reconnect.

<Tip>
  For deep history on start-up (large `count` values), raise `timeoutMs` beyond the default 15 seconds to allow the initial batch loading to complete.
</Tip>
